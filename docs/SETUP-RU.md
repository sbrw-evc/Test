# Внедрение новой версии Infinity и Prometheus

Интерфейс dashboard полностью на английском. Базовые пороги записаны числом `0` для совместимости с JSON editor, который подчёркивает `null`; данные API без значений остаются `No data`.

1. Использовать существующий Prometheus с kube-state-metrics и kubelet/cAdvisor. Проверить `kube_pod_status_ready`, `kube_pod_container_status_restarts_total`, `container_cpu_usage_seconds_total`, `container_memory_working_set_bytes`, `kube_pod_container_resource_requests/limits` и `kubelet_volume_stats_used/available/capacity_bytes`.
2. В Grafana проверить текущие Infinity datasources TeamCity/Jenkins/Octopus из `cicd-health/review-source-profile.json`. HTTP endpoints и относительный TeamCity URL сохранены из рабочего экспорта. Credentials хранить в secureJsonData, оставить действующие base URL/allowedHosts/TLS настройки. Prometheus UID также взят из экспорта; шаблон datasource YAML — только пример для новых установок.
3. Импортировать `cicd-health/cicd-health-dashboard.json` в Grafana v2. Он использует UID `cicd-operational-health` и пять главных RowsLayout блоков. При изменениях генератора выполнить `python scripts/build_operational_review.py` и `python scripts/validate_dashboard.py`.
4. Список пайплайнов/проектов обновляется непосредственно через API QueryVariables; отдельный cron discovery workflow не нужен. Выбрать Octopus Prod environment по имени, без угадывания IDs. Namespace scope зафиксирован двумя CI namespace; нижние filters не расширяют его.
5. Обеспечить read-only доступ Grafana к builds, queues, agents, server health, computer executors, deployment tasks/deployments/projects/environments/targets. Hidden metadata lookups используют текущие datasource credentials. Если поле/объект не виден аккаунту, оно не считается здоровым или существующим по умолчанию.
6. Выполнить [приёмку по ревью](REVIEW-RU.md). Она проверяет причины DEGRADED, source metadata, baseline, queues, worker limitations, PVC и annotations.
7. Для alert provisioning заполнить `monitoring-config.yml` по example и выполнить `python scripts/generate_monitoring.py monitoring-config.yml` с PyYAML. Указать реальный `prod_environment_id`; Octopus примеры paused до этого. API alerts используют фиксированные All scopes и последние 100 samples, не значения UI filters. Требования к каждому build/deploy event отдельно закрываются штатными notifications.
8. Проверить `cicd-health/grafana-alert-rules.yml` в staging, orgId, datasource UID и rules migration. Teams Workflow webhook и PagerDuty Events key хранить в secret manager. warning → Teams, critical → Teams+PagerDuty. Проверить firing/resolved и маршрутизацию DatasourceError/NoData, включая labels.
9. Отдельно согласовать thresholds queue=10, agents minimum=1, running age TC/Jenkins=1800s, Octopus=3600s, PVC=80/90%, restarts>3 за15m. PV forecast alert — линейная оценка, а не гарантия capacity.
10. После приёмки отключить только старые kit-owned native ServiceMonitor/Probe resources, если они не нужны другим dashboard. Общие Prometheus/KSM/kubelet monitoring не удалять. Архивный Word в docs/legacy описывает прежнюю схему, не текущее внедрение.

Локальная проверка: `python -m unittest discover -s tests -p 'test_*.py'` (jq), `python scripts/validate_dashboard.py`. PromQL дополнительно проверяется promql parser/promtool в DevOps environment. Эти проверки не заменяют live Grafana/API permission smoke tests.
