CI/CD HEALTH — НАСТРОЙКА INFINITY БЕЗ ДОСТУПА К KUBERNETES
=========================================================

В комплекте ровно два файла:
  dashboards/cicd-health.json — один большой dashboard;
  infinity-sources.txt — эта инструкция и точный список запросов.

CI/CD KPI читаются через REST API; метрики подов — из уже подключённого Prometheus. Никаких kubectl, Helm, изменений pod,
установки exporter или перенастройки существующего Prometheus не требуется.
Доступа к Kubernetes не нужно, но Grafana должна иметь сетевой доступ к API
TeamCity/Jenkins/Octopus, а служебная учётная запись — права чтения.
В ходе подготовки реальные API, Grafana и Kubernetes не опрашивались.

1. ОБЩИЕ НАСТРОЙКИ
------------------
В Grafana уже должен быть доступен Infinity с Backend → JQ (jq-backend).
Формат запроса: JSON; Source: URL; Method: GET; Body: отсутствует.
Query parameters, Root selector, Columns и JQ-расчёты уже находятся в JSON.
Ничего из JQ вручную переносить не нужно. Default dashboard refresh: 1 minute.
Ориентир совместимости: Grafana 11.6+ и Infinity 4.1.1. Если ваша установленная
версия отличается, проверьте наличие jq-backend и server-side expressions.
Для запросов нужен Accept: application/json. TLS certificate validation включена.
Timeout: 15 seconds. Allowed hosts: реальный HTTPS origin сервера, например
https://octopus.example.invalid (здесь и далее адреса вымышленные).
Не помещайте токены в URL, dashboard JSON или query headers.
Секреты задаются только в защищённых настройках datasource.

Важно: URL в запросах относительные. Base URL datasource — корень приложения,
БЕЗ /api или /app/rest и БЕЗ завершающего /. Например https://host.
Jenkins может иметь context path: https://host/jenkins, тогда GET /api/json
должен обращаться к https://host/jenkins/api/json.
Если имеющийся Octopus datasource настроен с Base URL https://host/api,
скорректируйте Base URL до https://host, сохранив текущую авторизацию/токен.
Это изменение настройки источника в Grafana, не изменение Kubernetes.

2. OCTOPUS — ИСПОЛЬЗУЙТЕ УЖЕ СУЩЕСТВУЮЩИЙ ИСТОЧНИК
-------------------------------------------------
Тип: Infinity. Новый источник создавать не требуется.
Base URL: https://<OCTOPUS_HOST> — корень приложения.
Allowed hosts: https://<OCTOPUS_HOST>.
Авторизацию и уже настроенный токен сохраните.
Если нужна сверка: обычно API key → In: Header → Key: X-Octopus-ApiKey;
Value: текущий API key в secure setting. Повторно вводить его не требуется,
если рабочая авторизация уже настроена через API key или custom secure header.
Permissions: чтение списка доступных Spaces, Projects и нужных Tasks, Workers, Deployment Targets.
Octopus Space — query dropdown: отображает Name, передаёт Id (Spaces-N).
Список загружается через существующий Octopus datasource и его текущий токен.
Недоступные учётной записи пространства не появятся в списке.
Octopus project обновляется при смене Space; выберите нужные проекты или All.

GET-запросы Octopus, используемые dashboard и dropdown variables:
  1) GET http://octopus.admortgage.com/api/${octopus_space}/tasks$__combineValues(?project=,,__comma,${octopus_project:csv})
     Query parameters (Infinity URL options → Params):
       name = Deploy
       states = Success,Failed,Canceled,TimedOut
       take = 100
     Используется: Octopus • Errors in 10 Minutes; Вся CI/CD цепочка; Octopus • Success of the last N; Octopus • Average duration • last N; Octopus; Successful • last N; Completed (SUCCESS/FAILURE) in the sample; Octopus • last 100 completed results in project

  2) GET http://octopus.admortgage.com/api/${octopus_space}/workers
     Query parameters (Infinity URL options → Params):
       take = 1000
     Используется: Octopus • Unavailable agents / workers; Octopus • Available agents / workers; Octopus; Available agents / workers; Unexpectedly unavailable agents/workers; Agents / workers • inventory

  3) GET http://octopus.admortgage.com/api/${octopus_space}/workerspus_space}/workers
     Query parameters (Infinity URL options → Params):
       take = 1000
     Используется: Вся CI/CD цепочка

  4) GET http://octopus.admortgage.com/api/${octopus_space}/tasks$__combineValues(?project=,,__comma,${octopus_project:csv})
     Query parameters (Infinity URL options → Params):
       name = Deploy
       states = New,Queued
       take = 1000
     Используется: Вся CI/CD цепочка; Octopus • Queue; Octopus; Queue

  5) GET http://octopus.admortgage.com/api/${octopus_space}/tasks$__combineValues(?project=,,__comma,${octopus_project:csv})
     Query parameters (Infinity URL options → Params):
       name = Deploy
       states = Executing,Cancelling
       take = 1000
     Используется: Вся CI/CD цепочка; Octopus • Longest-running build/deployment; Octopus; Longest current execution; Current executions

  6) GET http://octopus.admortgage.com/api/machines
     Query parameters (Infinity URL options → Params):
       take = 1000
     Используется: Deployment targets • separate from workers

  7) GET http://octopus.admortgage.com/api/spaces/all
     Query parameters (Infinity URL options → Params):
       отсутствуют
     Используется: Dropdown: Octopus Space

  8) GET http://octopus.admortgage.com/api/${octopus_space}/projects
     Query parameters (Infinity URL options → Params):
       take = 1000
     Используется: Dropdown: Octopus project

Octopus KPI используют tasks типа Deploy, а не все ServerTasks.
State Success — успех, Failed/TimedOut — failure, Canceled исключается
из процента успешности. Workers — исполнители, machines — deployment targets;
это разные сущности. Встроенный worker может отсутствовать в /workers.
Поэтому минимум внешних workers в общем health по умолчанию равен 0.
Если вы используете dedicated workers, отредактируйте threshold в health
expression Octopus (проверка $RC<0) на ваш минимум.
Для machines/targets health вынесен в отдельную таблицу.

3. TEAMCITY
-----------
Тип: Infinity; отдельный datasource.
Base URL: https://<TEAMCITY_HOST> — корень приложения.
Allowed hosts: https://<TEAMCITY_HOST>.
Authentication: Bearer token; Token — служебный TeamCity access token.
Header: Accept: application/json.
Permissions: чтение build configurations, builds, build queue и agents в нужных проектах.
/app/metrics и право View usage statistics этому варианту не требуются.

GET-запросы TeamCity, используемые dashboard и dropdown variables:
  1) GET /app/rest/builds
     Query parameters (Infinity URL options → Params):
       locator = $__combineValues(buildType:__openid:,__close__comma,__comma,${teamcity_pipeline:csv})state:finished,branch:default:any,count:100
       fields = nextHref,build(id,buildTypeId,number,status,state,startDate,finishDate,webUrl,canceledInfo,agent(id))
     Используется: TeamCity • Успешность последних N; TeamCity • Средняя длительность • последние N; Вся CI/CD цепочка; TeamCity; Успешность • последние N; Завершённые SUCCESS/FAILURE в выборке; TeamCity • последние 100 завершённых результатов; TeamCity • Ошибки за 10 минут

  2) GET /app/rest/agents
     Query parameters (Infinity URL options → Params):
       locator = defaultFilter:false,count:1000
       fields = nextHref,agent(id,name,connected,enabled,authorized)
     Используется: TeamCity • Доступные агенты / workers; Вся CI/CD цепочка; TeamCity; Доступные агенты / workers; Неожиданно недоступные агенты / workers; Агенты / workers • инвентарь; TeamCity • Недоступные агенты / workers

  3) GET /app/rest/buildQueue
     Query parameters (Infinity URL options → Params):
       locator = $__combineValues(buildType:__openid:,__close__comma,__comma,${teamcity_pipeline:csv})count:1000
       fields = nextHref,build(id,buildTypeId)
     Используется: TeamCity • Очередь; Вся CI/CD цепочка; TeamCity; Очередь

  4) GET /app/rest/builds
     Query parameters (Infinity URL options → Params):
       locator = $__combineValues(buildType:__openid:,__close__comma,__comma,${teamcity_pipeline:csv})state:running,branch:default:any,count:1000
       fields = nextHref,build(id,buildTypeId,number,status,state,startDate,finishDate,webUrl,canceledInfo,agent(id))
     Используется: TeamCity • Самая долгая текущая сборка / деплой; Вся CI/CD цепочка; TeamCity; Самое долгое текущее выполнение; Текущие выполнения

  5) GET /app/rest/buildTypes
     Query parameters (Infinity URL options → Params):
       locator = count:1000
       fields = nextHref,buildType(id,name,projectName)
     Используется: Dropdown: TeamCity pipeline

Сборки читаются по всем веткам: branch:default:any.
SUCCESS — успех; FAILURE — failure; canceledInfo/UNKNOWN — canceled.
Доступные агенты: connected && enabled && authorized.
Недоступные агенты: !connected && enabled && authorized.
Это не число свободных compatible agents для конкретной конфигурации.

4. JENKINS
----------
Тип: Infinity; отдельный datasource.
Base URL: https://<JENKINS_HOST> или https://<HOST>/<JENKINS_CONTEXT>.
Allowed hosts: HTTPS origin вашего Jenkins.
Authentication: Basic authentication.
User: служебный Jenkins user; Password: его Jenkins API token (secure setting).
Permissions: Overall/Read, Job/Read и чтение состояния агентов.
Jenkins Prometheus Plugin этому варианту НЕ требуется.
GET запросы API не требуют crumb, если стандартная Jenkins конфигурация
принимает API token для аутентификации.

GET-запросы Jenkins, используемые dashboard и dropdown variables:
  1) GET /$__combineValues(,/,,${jenkins_pipeline:csv})api/json
     Query parameters (Infinity URL options → Params):
       tree = fullName,url,builds[number,result,building,timestamp,duration,url]{0,100},jobs[fullName,url,builds[number,result,building,timestamp,duration,url]{0,100},jobs[fullName,url,builds[number,result,building,timestamp,duration,url]{0,100},jobs[fullName,url,builds[number,result,building,timestamp,duration,url]{0,100},jobs[fullName,url,builds[number,result,building,timestamp,duration,url]{0,100},jobs[fullName,url,builds[number,result,building,timestamp,duration,url]{0,100},jobs[name,_class]]]]]]
     Используется: Jenkins • Успешность последних N; Вся CI/CD цепочка; Jenkins • Средняя длительность • последние N; Jenkins • Самая долгая текущая сборка / деплой; Jenkins; Успешность • последние N; Завершённые SUCCESS/FAILURE в выборке; Самое долгое текущее выполнение; Jenkins • последние 100 завершённых результатов; Текущие выполнения; Jenkins • Ошибки за 10 минут

  2) GET /computer/api/json
     Query parameters (Infinity URL options → Params):
       tree = computer[displayName,offline,temporarilyOffline,numExecutors,idle]
     Используется: Jenkins • Доступные агенты / workers; Вся CI/CD цепочка; Jenkins; Доступные агенты / workers; Неожиданно недоступные агенты / workers; Агенты / workers • инвентарь; Jenkins • Недоступные агенты / workers

  3) GET /queue/api/json
     Query parameters (Infinity URL options → Params):
       tree = items[id,task[fullName]]
     Используется: Вся CI/CD цепочка; Jenkins • Очередь; Jenkins; Очередь

  4) GET /api/json
     Query parameters (Infinity URL options → Params):
       tree = jobs[fullName,_class,jobs[fullName,_class,jobs[fullName,_class,jobs[fullName,_class,jobs[fullName,_class,jobs[name,_class]]]]]]
     Используется: Dropdown: Jenkins pipeline

Параметр tree длинный: он выбирает вложенные jobs/folders и необходимые поля
builds. Он уже полностью задан в dashboard JSON. Поддерживается 4 уровня
вложенных folders/multibranch containers с получением builds на конечных jobs.
Если структура глубже, dashboard отвергает неполный leaf вместо ложного SUCCESS;
увеличьте вложенность tree в соответствующих запросах через Query editor.
All: N=100 завершённых глобально выбираются из последних 100 builds каждого job.
Выбранный job запрашивается напрямую; используется до 100 завершённых
результатов из его последних 100 builds. Текущие builds исключены из успешности.
SUCCESS — успех, FAILURE и UNSTABLE — failure; ABORTED/NOT_BUILT исключаются
из успешности. Online nodes с numExecutors>0 и без temporarilyOffline
считаются доступными агентами. Controller с 0 executors не учитывается.
Executor slots не равны количеству nodes.

5. ИМПОРТ ОДНОГО DASHBOARD
-------------------------
1) В Grafana: Dashboards → New → Import → Upload JSON file.
2) Выберите dashboards/cicd-health.json.
3) В четырёх datasource selectors:
   Octopus → уже существующий Infinity datasource с настроенным токеном;
   TeamCity → Infinity datasource TeamCity;
   Jenkins → Infinity datasource Jenkins.
   Prometheus → уже подключённый источник, который собирает данные по подам.
   Для Prometheus ничего заново создавать или подключать не требуется.
   Названия и UIDs источников произвольные: импорт сопоставит их автоматически.
4) Выберите пространство в dropdown Octopus Space (список из /api/spaces/all).
5) Выберите TeamCity pipeline, Jenkins pipeline и Octopus project или All.
   Namespace и Pod — dropdown из существующего Prometheus с multiselect/All.
   Pod зависит от выбранного Namespace. All использует regex .* для подов.
   Проверьте Query Inspector по одному запросу каждой системы.
   Save & Test datasource сам по себе не гарантирует правильность всех API queries.
6) Один dashboard содержит overview, KPI, history, running builds/tasks,
   agent/worker inventory и Octopus targets. Секции развёрнуты по умолчанию.
   Карточки/навигация ведут к таблицам того же dashboard, а не к отдельным JSON.

Обновление старого варианта: импортировать этот JSON с UID
cicd-operational-health с подтверждением overwrite. Предыдущие вручную
созданные alert rules/provisioning не изменяются самим импортом JSON.
Этот пакет теперь состоит только из dashboard и данной инструкции.
Если прежняя версия была provisioned администратором, право её overwrite
в UI зависит от настроек Grafana. При запрете выберите новый UID при импорте
и поправьте внутренние /d/cicd-operational-health ссылки в dashboard settings
и panel links на новый UID. Изменения Kubernetes для нового импорта не нужны.

6. СМЫСЛ HEALTH И ОГРАНИЧЕНИЯ
----------------------------
ЗДОРОВ: API данные успешно прочитаны, queue <=10, нет неожиданно offline,
доступных агентов >=1 для TeamCity/Jenkins, нет failure за последние 600 sec,
текущие builds <=1800 sec, Deploy tasks <=3600 sec.
ДЕГРАДАЦИЯ: API отвечает, но нарушен один из этих KPI.
НЕТ ДАННЫХ: запрос не выполнен, 401/403, timeout или неполный ответ.
Последнее не различает серверный сбой, ошибку токена и сетевую недоступность;
смотрите конкретную ошибку Query Inspector. HTTP response time и историческая HTTP availability не включены,
поскольку для них нужен отдельный источник/probe, отсутствующий в этом пакете.
CPU/RAM/pod readiness/restarts включены из уже имеющегося Prometheus.
Pod-показатели не входят в общий API health, они показаны в отдельном блоке. Query Inspector показывает время выполнения
самого запроса, но это не отдельный временной ряд HTTP latency.

Успешность — SUCCESS/(SUCCESS+FAILURE) в последних N=100 завершённых результатах.
Canceled исключены; средняя длительность учитывает завершённые результаты
с start/finish timestamps, включая canceled. Пустая выборка — Нет данных,
а не искусственные 100%. CI/CD KPI — текущие API snapshots; time picker не превращает их в историю.
Раздел подов использует существующие Prometheus time series и выбранный период.
Inventory/running limits: 1000. TeamCity nextHref и Octopus TotalResults,
указывающие на обрезанную выборку, вызывают ошибку вместо ложного здоровья.

Несколько панелей могут опрашивать один и тот же endpoint отдельно.
Список выше — уникальные URL+parameters, не обещание одного HTTP запроса
в минуту на каждый URL. Большой Jenkins tree и частый refresh создают нагрузку;
при необходимости уменьшите scope/jobs/N и увеличьте refresh в Grafana UI.
Не гарантируется уведомление на каждое событие между опросами последних N.

JSON не создаёт alert rules и contact points. При необходимости алерты
можно настроить вручную в Grafana по этим backend JQ queries; в alert query
нужно задать конкретный datasource UID и Space ID, поскольку dashboard
variables не доступны при фоновой оценке. Настройки Teams/PagerDuty относятся
к Grafana, а не к Kubernetes. Токены и уведомления в этой подготовке не менялись.

Использована композиция Stat/Gauge/цветных таблиц; чужие JSON не копировались.

7. УЖЕ ПОДКЛЮЧЁННЫЙ PROMETHEUS
-----------------------------
Выбирается при импорте через DS_PROMETHEUS. Настройки подключения, токены,
scrape jobs и Kubernetes не меняются. Нужные уже собранные series:
  kube_pod_status_ready{condition="true"} — готовность подов;
  kube_pod_container_status_restarts_total — счётчик рестартов;
  container_cpu_usage_seconds_total — CPU containers;
  container_memory_working_set_bytes — память containers.
Фильтры: namespace=~"${namespace:regex}", pod=~"${pod:regex}".
Dropdown запрашивают label_values по перечисленным выше series (и kube_pod_info,
если она уже есть). Namespace не требует отдельно установленного kube-state-metrics.
Pod dropdown ограничен namespace. Значения выбираются из series выбранного
периода Prometheus; variable refresh — On time range change.
Regex formatting безопасно экранирует имена и объединяет multiselect через |.
CPU: sum by(namespace,pod)(rate(...[$__rate_interval])).
RAM: sum by(namespace,pod)(container_memory_working_set_bytes{...}).
Рестарты: sum by(namespace,pod)(increase(...[$__range])).
Если имена metrics/labels в вашем источнике отличаются, скорректируйте PromQL
через Edit panel → Query. Если kube-state-metrics/cAdvisor series не собираются,
соответствующий график останется «Нет данных» — dashboard не устанавливает их.
Это использование текущих данных, а не требование доступа к Kubernetes.

8. ИСПРАВЛЕНИЕ REDUCE EXPRESSION
-------------------------------
Если старая версия JSON выдаёт:
  failed to parse expression [RA]: reducer mode 'strict' is not supported
это ошибка сериализации Reduce settings, а не ошибка токена Octopus.
В обновлённом JSON settings.mode удалён из всех Reduce expressions.
Strict является режимом по умолчанию; явно допустимы только dropNN/replaceNN.
Null/NaN не заменяются нулём и пропуски не скрываются.
Импортируйте обновлённый JSON с overwrite того же UID, выбрав существующие
три Infinity datasource и Prometheus. После импорта выберите пространство в Octopus Space dropdown.
Для точечного исправления без повторного импорта: в JSON модели панели
у всех targets с type=reduce удалите объект settings:{mode:"strict"}.
Не меняйте авторизацию источника ради устранения этой ошибки.
Подтверждение: Grafana pkg/expr/commands.go, UnmarshalReduceCommand:
https://github.com/grafana/grafana/blob/main/pkg/expr/commands.go

9. ФИЛЬТРЫ ПАЙПЛАЙНОВ И ГРАНИЦЫ ВЫБОРКИ
-----------------------------------------
Все шесть фильтров — Query variables; их запросы уже находятся в JSON.
Для Infinity используется queryType=infinity, Backend JQ, Format=Table,
колонки __text и __value. Names отображаются пользователю, IDs используются
в запросах. Списки обновляются при загрузке dashboard; Reload dashboard
обновляет каталог. Смена Space обновляет зависимый список проектов.

TeamCity pipeline: buildType.id; название Project / Build configuration.
Jenkins pipeline: отображается fullName конечного job, включая folders/multibranch branch;
значение — URL path job/.../job/... с percent-encoding каждого имени.
Octopus project: Project.Id из выбранного Space.
Фильтры независимы: автоматического соответствия job ↔ buildType ↔ project нет.
TeamCity pipeline, Jenkins pipeline и Octopus project: одиночный выбор,
Include All, Custom all value = *.
All убирает серверное ограничение конфигурации/проекта; выводится общая выборка.
Jenkins All запрашивает общий каталог jobs; конкретный job — его собственный API.
TeamCity/Octopus IDs и Jenkins job path используются в API queries.
Для Jenkins queue применяется точное сравнение job path, без regex-сопоставления.

Выбор влияет на успех/ошибки, длительность, текущие выполнения, очередь,
таблицы истории и соответствующие проверки health (включая общую карточку).
API availability, агенты/workers и deployment targets остаются общими для системы
или Space; Prometheus pod-фильтры независимы от пайплайнов. Количество агентов
не означает количество свободных агентов, совместимых с выбранным pipeline.

TeamCity/Octopus: ограничение конфигурации/проекта передаётся серверу ДО count/take.
История: до 100 завершённых результатов выбранной конфигурации TeamCity либо
проекта Octopus. All: до 100 результатов всего сервера TeamCity или Space Octopus.
Фильтр применён к истории, успешности, длительности, ошибкам, running и очереди,
включая запросы общей карточки health. Running/queue limits остаются 1000.
Агенты, workers и поды сохраняют свой общий охват.
Jenkins: выбор job меняет URL API. История/KPI получают данные только этого job.
All выбирает последние 100 завершённых результатов глобально из полученных
последних 100 builds каждого job. Выполняющиеся builds исключены из истории.

Каталоги TeamCity buildTypes и Octopus projects имеют лимит 1000. Если ответ
обрезан, JQ выдаёт ошибку: увеличьте limit в соответствующей variable query.
Jenkins dropdown и панели имеют одинаковую глубину tree (4 уровня folders).
Права доступа могут ограничить любой из каталогов и данные API.
Фильтры не создают фоновые alert rules: для алертов нужны фиксированные scope/IDs,
а не dashboard variables.

Документация переменных и каталогов:

https://octopus.com/docs/octopus-rest-api/examples/spaces
https://octopus.com/docs/api/projects
https://www.jetbrains.com/help/teamcity/rest/manage-build-configuration-details.html

10. СЕРВЕРНЫЙ ФИЛЬТР TEAMCITY / OCTOPUS
--------------------------------------
TeamCity: locator начинается с
  $__combineValues(buildType:__openid:,__close__comma,__comma,${teamcity_pipeline:csv})
При выбранной конфигурации это buildType:(id:<BuildTypeId>), а при All — пустая строка.
Остальная часть locator сохраняет state, branch и count нужного запроса.
Octopus: URL tasks заканчивается макросом
  $__combineValues(?project=,,__comma,${octopus_project:csv})
При выборе проекта добавляется ?project=Projects-N; All не передаёт project.
name/states/take задаются только в URL options → Params, без дублирования в URL.
Старые клиентские JQ фильтры TeamCity/Octopus удалены.
Проверены 102 выполнения JQ и раскрытие macros на тестовых данных, включая
редкую конфигурацию со 150 запусками, не попадающими в общие последние 100.
Реальные API и Grafana не опрашивались.

11. JENKINS: ОДИНОЧНЫЙ JOB И ALL
--------------------------------
Variable jenkins_pipeline возвращает Name=fullName и Value=job/<encoded-name>/job/...
Пример: team/frontend → job/team/job/frontend.
Для multibranch feature%2Flogin получается feature%252Flogin в URL path.
Query URL:
  /$__combineValues(,/,,${jenkins_pipeline:csv})api/json
Выбор job: /job/team/job/frontend/api/json; All: /api/json.
Parser нормализует ответ job или controller к одному формату; старый JQ-фильтр
истории удалён. Очередь /queue/api/json читается целиком и фильтруется по job;
неизвестные task без fullName не включаются в выбранный job, но входят в All.
Агенты и executors сохраняют общий охват. Чтение folders для All — 4 уровня.
Проверены 81 выполнение JQ: выбранный job/All/пустая история, вложенные folders,
кириллица, пробелы, percent-encoded имена branch, фильтрация очереди.
Живые Jenkins/Grafana не опрашивались.

12. ВЫБОР ЧАСОВОГО ПОЯСА
------------------------
Variable display_timezone: Москва = Europe/Moscow, Майами = America/New_York.
Выберите значение в dropdown и нажмите dashboard link «Применить часовой пояс».
Ссылка передаёт native Grafana timezone URL parameter, сохраняя диапазон времени
и все переменные. Относительный URL сохраняет префикс /grafana при его наличии.
Часовой пояс по умолчанию: Europe/Moscow. В колонках Start/Finish отображается
${__timezone} — именно фактически применённый часовой пояс, а не ещё не
применённый выбор в dropdown. Выбор без нажатия ссылки timezone не меняет.
Москва: UTC+03:00. Майами использует America/New_York: UTC−04:00 летом,
UTC−05:00 зимой; переходы обрабатывает Grafana. Timestamp не сдвигается вручную,
поэтому фильтрация, длительность и расчёт KPI не меняются от выбора timezone.
Если timezone переопределён в URL, Grafana использует его поверх default.
